# 悬窗文档整理

点击悬窗右上角的书本图标打开文档库。文档按日期分组，可选择最近导入、最早导入或标题排序；搜索框同时查论文标题、原始文件名和历次导入别名。「加载更多」继续读取服务端文档，清空已完成任务不会清空文档库。


| 导入情况 | 整理结果 |
| --- | --- |
| 同一 PDF 换了文件名 | 复用同一文档，增加导入记录，旧名字仍可搜索 |
| 只改变 PDF 元数据或压缩方式，内容指纹相同 | 复用同一文档 |
| 同一论文标题，正文、图或其他内容改变 | 保留独立文档，标题前显示内容版本编号及首次导入时间 |
| 不同论文碰巧用了同一文件名 | 保留各自内容，根据识别出的论文标题显示 |

重复导入已完成的文档会复用译文；正在翻译的文档继续显示进度，不会自动启动第二次翻译。失败和待翻译文档仍使用原有提交流程。仅标题相同或文字相似不能作为合并依据；所有整理和查询按登录账号隔离。

系统优先使用有效的 PDF 标题元数据，再从首页拼接标题，排除常见的期刊页眉、模板标题、竖排 arXiv 边栏和 DOI；识别失败时使用上传文件名。默认显示完整标题，长度受限。需要自己的简写时，可在网页论文详情编辑标题；原始标题和文件名仍可检索，内容版本关系继续保留。

点击文档右侧菜单可查看导入记录、同标题的内容版本，或定位译文。记录显示导入时间与当时文件名；历史接口最多返回最近 200 条导入记录，文档分页每次 50 份。

「整理已有文档」为旧记录建立内容指纹、版本和导入历史，并更新明显由文件名生成或截断的标题；也会修正已索引的自动无效标题。用户修改的名称保留。旧重复记录不删除，既有链接、原文、译文、任务、标签和笔记保留。首次批量整理需要读取原文，扫描大文档时可能较慢。

旧重复记录有多份已完成译文时，优先显示最近成功完成的一份，避免打开后来修复之前的旧版；最早导入时间和各次导入记录仍保留，旧记录通过原链接可访问。

查看或定位译文时，本机缓存会使用以下结构：

```text
PDFs/2026-10/
  Molecular Systems--012345abcdef/
    Molecular Systems--20261011-111200--012345abcdef--中文.pdf
    Molecular Systems--20261011-111200--012345abcdef--双语.pdf
```

文件名中的时间为文档记录创建时间，目录月份及显示日期使用本机时区。完整 ID 防止同名文档互相覆盖。刷新文档库时，已加载文档的旧缓存也会归档；已有目标文件不会被旧缓存覆盖。原始上传文件仍保存在服务端稳定路径，本机下载源文件不被移动或改名。

服务端原文、中文及双语下载使用论文标题、时间和 ID 命名。译文缓存及记录保存在 `~/Library/Application Support/SuperTranslate/Floating/`，按服务与登录会话隔离，权限仅当前用户可读写。

网页分片续传和悬窗常规上传共享文档指纹：相同内容跨两端复用同一记录、译文和导入别名。分片完成的文档、导入记录与续传状态在同一事务保存；重复提交完成请求不会多记导入次数。旧续传记录可以通过整理补建索引。上一轮部署证据见 [CLIENTS_RELEASE_20261027.md](CLIENTS_RELEASE_20261027.md)，本次修复验证见 [CLIENTS_RELEASE_20261027.md](CLIENTS_RELEASE_20261027.md)。
