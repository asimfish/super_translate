# ADR-0005: 可扩展的分类与论文术语库

## Status
Accepted

## Context
现有文件语料集中在 AI 领域，加载时将所有分类展平。同一英文词在不同学科有不同译法时，最后加载的值覆盖前值；用户不能从网页维护或给单篇论文设置译法。

## Candidates
| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 继续增加 JSON 分类和文件编辑器 | 沿用 CLI，结构简单 | 并发写入、账号隔离、论文绑定和冲突检查难以保证 |
| 在现有 SQLite 中增加分类、库、词条和设置表 | 事务导入、按账号管理、可复用分类与论文专用库 | 增加 API 和网页管理；翻译需传递术语快照 |

## Decision
选择 SQLite 管理可编辑库，保留文件语料为只读内置 AI 库。仅新增表，不改写论文、凭据和历史语料。分类根节点代表学科，子节点代表领域，可继续嵌套，名称和分类由用户维护，不以固定枚举限制新学科。

接口：`/api/terminology/categories`、`/libraries`、`/libraries/{id}/entries`、`/import`、`/export`、`/profile`、`/papers/{id}/profile` 和 `/resolve`。导入导出采用带版本的 JSON，批量输入兼容 UTF-8 CSV。

优先级：内置库（可关）→ 通用库 → 分类祖先库（学科到领域）→ 显式选用的库（保存顺序）→ 论文专用库。相同优先级按创建顺序、ID 确定结果，并报告冲突来源。停用库不参与解析；论文专用库不会用于其他论文。未设置论文继承工作区默认设置，悬窗新上传也使用该默认。没有任何设置时保留历史行为。

翻译在读取论文的短事务中解析术语，随后将独立快照随配置传入隔离工作进程和供应商实例，不使用进程全局变量。按术语内容生成缓存文件后缀，防止旧译文缓存跨配置重用。译后术语检查使用同一个 worker 配置快照。术语约束仅适用于八家 AI 供应商的标准/高质量模式，快速 Google 翻译不支持。

## Invariants and acceptance
- 所有分类、库、词条、绑定、导出和预览均按认证 scope 查询；跨账号 ID 返回 404。
- 分类改名、库迁移分类、词条编辑、停用及有界原子导入有网页入口；非空分类删除返回冲突，删除库级联词条。
- 化学、生物提供可选入门模板；内置 AI 库可搜索、导出和复制，不原地改写发布语料。
- JSON/CSV 导入默认遇到已有词条保持原值，可显式选择覆盖；非法行或重复源词使整批回滚。
- 分类最多 8 层；工作区最多 500 分类、200 库、20,000 自定义词条；每库最多 5,000，每次导入最多 1,000 行和 2 MiB。
- 同词跨领域隔离、论文覆盖、别名、停用、账号隔离、事务失败和缓存更新须有行为证据；网页须验证新增分类/库/词条、批量输入及论文设置和移动布局。

## Impact
术语匹配函数 upstream 分析为 HIGH（2 个直接生产调用点、12 个影响符号、术语 QA 流程）；提示构建、翻译路由与 worker 接入低风险，供应商实例中等风险且接口动态调用的索引统计为下界。保留可选参数和旧配置默认值，先验证旧语料/翻译回归，再发布。数据库更新为新增表，可保留数据回退旧程序；不删除或修改现有表和语料文件。
